# Data documentation

Generated by `python src/download_data.py`. The exact download date and row counts are written to
`dataset_info.json` when the script runs. Copy that date into the report.

## Dataset: `weather_pakistan.csv`
- **Unit:** one row = one city on one day (local time, Asia/Karachi).
- **Cities (4):** Karachi (coastal, dry), Lahore (monsoon plains), Islamabad (wettest), Quetta (mountains, winter rain).
- **Period:** 2020-01-01 to 2024-12-31. Raw data was downloaded for 2010–2024; only the most recent 5 years are
  kept, to keep training time manageable. Late-2019 days are still used for the look-back features of early 2020.
  The last day of each city is dropped because it has no "tomorrow".
- **Size:** 7,304 rows and **16 model features** (15 numeric + city), plus `date` and the target.
  All 40 collected features are kept in `weather_pakistan_all_features.csv`. The 16 were selected using **only the
  training years 2020–2022**: permutation importance (model fitted on 2020–21, scored on 2022), skipping features with
  |r| ≥ 0.9 to an already chosen one, and stopping when importance is no longer positive (notebook section 1.1).

**The 16 model features:**
- `city`, `month`
- from Open-Meteo: `temperature_2m_max`, `pressure_msl_mean`, `cloud_cover_mean`, `wind_speed_10m_max`,
  `wind_direction_10m_dominant`, `precipitation_sum`
- from NASA POWER: `nasa_cloud_amt`, `nasa_prectotcorr`, `nasa_ps`, `nasa_rh2m`, `nasa_qv2m`
- look-back: `precip_3d_sum`, `precip_7d_sum`, `pressure_change_24h`

## Source 1: Open-Meteo Historical Weather API
| | |
|---|---|
| URL | https://archive-api.open-meteo.com/v1/archive (docs: https://open-meteo.com/en/docs/historical-weather-api) |
| Underlying data | ECMWF ERA5 / ERA5-Land reanalysis (plus ECMWF IFS from 2017), served by Open-Meteo |
| Collection method | HTTP GET per city in 5-year chunks, `timezone=Asia/Karachi`, with our own Python script |
| Daily variables | temperature max/min/mean, precipitation sum, rain sum, precipitation hours, max wind speed, max gust, dominant wind direction, shortwave radiation sum, ET₀ evapotranspiration, sunshine duration, plus elevation |
| Hourly → daily (by us) | relative humidity mean/max/min, dew point mean, sea-level pressure mean/min, cloud cover mean |
| Licence | **CC BY 4.0**: attribution required ("Weather data by Open-Meteo.com", https://open-meteo.com/en/licence) |
| Citation | Zippenfenig, P. (2023). *Open-Meteo.com Weather API*. Zenodo. doi:10.5281/zenodo.7970649. ERA5: Hersbach et al. (2020), QJRMS 146, 1999–2049 |

## Source 2: NASA POWER Daily Point API
| | |
|---|---|
| URL | https://power.larc.nasa.gov/api/temporal/daily/point (docs: https://power.larc.nasa.gov/docs/services/api/temporal/daily/) |
| Underlying data | NASA GMAO MERRA-2 (meteorology) and CERES / FLASHFlux (solar), about 0.5° grid |
| Collection method | HTTP GET per city, `community=AG`, 2010–2024, JSON; −999 fill values replaced with missing |
| Variables (prefix `nasa_`) | T2M, T2MDEW, RH2M, QV2M, PS, WS2M, WS10M, CLOUD_AMT, ALLSKY_SFC_SW_DWN, PRECTOTCORR |
| Licence | No restrictions on use; the POWER team requests acknowledgement (https://power.larc.nasa.gov/docs/referencing/) |
| Citation | "The data was obtained from the NASA Langley Research Center (LaRC) POWER Project funded through the NASA Earth Science/Applied Science Program." State the POWER version and access date (see `dataset_info.json`). |

## How the two sources are combined
The two sources are joined on `city` + `date` (left join on Open-Meteo dates). Then, per city, in date order,
using **only today and earlier days** (all computed; the ones in **bold** are among the 16 model features):

| Feature | Meaning |
|---|---|
| `precip_lag1` | yesterday's precipitation |
| **`precip_3d_sum`**, **`precip_7d_sum`** | precipitation over the last 3 / 7 days, including today |
| `rain_days_7d` | rain days (≥ 1 mm) in the last 7 days |
| **`pressure_change_24h`**, `rh_change_24h`, `temp_change_24h` | change since yesterday |
| `month`, `day_of_year` | calendar position (`month` is used, encoded as sin/cos inside the pipeline) |

More features are created inside the model pipeline (`is_monsoon`, `rained_today`, cyclical month sin/cos). These are row-wise, so they cannot leak.

## Known limitations
- Reanalysis values are grid-cell averages (about 25 km for ERA5, about 50 km for MERRA-2), not rain-gauge readings.
- NASA POWER dates are in local solar time and Open-Meteo dates in Pakistan time, so the boundaries can differ by
  under an hour.
- The two sources estimate some of the same quantities (e.g. humidity) with different models. The EDA
  correlation matrix shows the overlap.
